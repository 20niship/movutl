# 座標系・基点・文字揃え・グループ制御の仕様

movutlの現状調査結果と、AviUtl / After Effects / Premiere Proの仕様、movutlで採用する統一仕様案をまとめる。

- 「現状」の章はソース(`movutl/asset/*.cpp`, `command/exo/exo_import.cpp`)を実際に読んで確認した内容。
- 「AviUtl/AE/Premiere」の章は既知の仕様に基づく記述。**(要検証)** と付いた項目は実機で確認してから実装すること。

---

## 1. movutlの現状(原点・基点)

### 1.1 Entityごとの原点が不統一

| Entity | 位置プロパティ | 原点の意味 | 根拠 |
|---|---|---|---|
| Movie | `pos`(Vec3) | **コンポ中心からのオフセット**(AviUtl相当)。画像中心が `コンポ中心 + pos` に来る | `movie.cpp` `base_x = (cw - img_w)/2 + pos[0]` |
| Image | `pos`(Vec3) | **画像左上のコンポ座標**(左上原点) | `image.cpp` `copyto(target, Vec2d(pos[0], pos[1]), ...)` |
| Shape | `pos_` | **左上のコンポ座標**(枠線の余白分だけ`shape_offset_`でずれる) | `shape.cpp` `pmin = pos_ + shape_offset_` |
| Text | `pos_` | **左上のコンポ座標**(枠線の余白分だけ`text_offset_`でずれる) | `text.cpp` `center = pos_ + text_offset_ + size*scale/2` |

`Image::copyto(dst, pmin, scale, angle, ...)` の第2引数は**画像左上(pmin)**であり、回転・拡大は**画像自身の中心**まわりで行う(`image.cpp:128-`)。基点(ピボット)を指定する手段は無い。

### 1.2 確認できた不具合

1. **`Entity::anchor_` は事実上機能していない**
   - Image / Shape / Text は `anchor_` を一切参照しない。
   - Movie は `anchor_` を**2回**足している(`base_x = anchor_[0] + ... `、さらに `center = base + anchor_`)。しかも回転・拡大の基点ではなく単なる平行移動として作用する。
2. **スケールが等方のみ**: Movie/Imageは `scale.avg()`、Textは `(scale_x_+scale_y_)/2` に潰している。`縦横比`(aspect)を表現できない。
3. **単位が不統一**: 拡大率は Movie=% / Image=0-1 / Text=0-1、回転は Movie=度(そのまま`copyto`へ) / Image=`rotation`をそのまま`copyto`(度扱い) / Shape,Text=ラジアン→度変換、透明度は 0-255 と 0-1 が混在。
4. **exoインポートで位置がずれる**: exoの`X,Y`は「画面中心からのオフセット(画像中心の位置)」だが、`exo_import.cpp`は全Entityの`pos`へ**そのまま代入**している。
   - Movie: 正しい(原点が同じ)。
   - **Image / Shape / Text: 画面左上原点として解釈されるため、`X=0,Y=0`(=画面中央)が画面左上隅に、しかも画像左上がそこに来る**。中央に置くには `pos = (cw - w)/2 + X` が必要。
5. 回転の符号・単位は上記のとおりバラバラなので、統一前に各Entityで正負(時計回りが正)を要確認。

## 2. AviUtl の仕様

### 2.1 座標系
- 原点は**画面(シーン)中心**、**Xは右が正・Yは下が正**。Zは奥が正。単位はpx。
- `標準描画`の `X, Y, Z` は「**オブジェクト中心(=基点)の位置**」。何もしなければ画像の中心が基点。
- 拡大率は%、回転は度(Z軸回転は**時計回りが正**) **(要検証)**、透明度は0-100で100が完全透明。

### 2.2 中心(基点) `cx, cy, cz`
拡張描画の `中心X/Y/Z` = obj変数 `obj.cx/cy/cz`。**画像中心から見た基点のオフセット**。

```
p         : 画像中心を原点とした画像内の点
p_screen  = (X,Y,Z) + R · S · ( p - (cx,cy,cz) )
S         = zoom(%) と aspect による縦横のスケール
R         = 回転(X,Y,Z軸)
```

- `cx` を正にすると、基点が画像の右側へ移り、**画像は左へ動いて見える**(基点が `X,Y` に固定されるため)。AEでアンカー値だけを変えたときと同じ動き。
- 回転・拡大は**基点を中心**に行われる。
- 3D回転の適用順は **(要検証)**。

### 2.3 obj変数(スクリプト)との対応
| 変数 | 意味 |
|---|---|
| `obj.x, y, z` | オブジェクトの基準座標(読み取り専用) |
| `obj.ox, oy, oz` | 基準座標に足す相対座標(描画時) |
| `obj.cx, cy, cz` | 中心(基点)オフセット |
| `obj.zoom, aspect, alpha` | 拡大率(1.0=100%)、縦横比、不透明度(1.0=不透明) |
| `obj.rx, ry, rz` | X/Y/Z軸回転(度) |
| `obj.w, h` | 現在の画像サイズ |

- `obj.setanchor(name,num[,option])` は**基点とは別物**で、ビューア上にドラッグできる制御点を出す機能。`cx/cy` とは連動しない。
- `obj.draw()` 引数省略時は上記obj変数の現在値を使う。`ox`の適用位置(回転の前か後か)は **(要検証)**。

### 2.4 テキストの「揃え」(`align`)
exoの`align`は0〜8(以降は縦書き系 **(要検証)**):

| 値 | 0 | 1 | 2 |
|---|---|---|---|
| 上段 | 左寄せ[上] | 中央寄せ[上] | 右寄せ[上] |
| 中段(3,4,5) | 左寄せ[中] | 中央寄せ[中] | 右寄せ[中] |
| 下段(6,7,8) | 左寄せ[下] | 中央寄せ[下] | 右寄せ[下] |

(値と並びは上の3×3で 0-2=上段、3-5=中段、6-8=下段。)

**揃えは「文字ブロックのどの点が基点(X,Y)に来るか」を決める**と理解してよい。
- 中央寄せ[中](=4): ブロックの中心が基点。他のオブジェクトの既定(画像中心)と一致。
- 左寄せ[上](=0): ブロックの**左上**が基点。文字数が増えると右・下へ伸び、左上は動かない(テロップで左端を固定したい用途)。
- 複数行のときは、行どうしの揃え(左/中央/右)も同じ値で決まる。
- **回転・拡大の中心もこの揃え基準点になる**という理解が有力だが、**(要検証)**。→ ユーザー予想「中央揃えのときはテキスト中央が既定の基点、左揃えなら左端が基点」はこの理解と一致する。

換算式(ブロックサイズ `w×h`、揃えの基準点オフセットを `a` とする):

```
a = ( ax * w/2 , ay * h/2 )        ax: 左=-1 中央=0 右=+1
                                    ay: 上=-1 中=0 下=+1
実効基点 = obj.c(x,y) + a           ← 画像中心から見た基点オフセット
p_screen = (X,Y) + R · S · ( p - 実効基点 )
```

`X,Y`は基点の位置なので、**揃えを変えても基点の画面位置は動かず、文字ブロックが動く**。

### 2.5 グループ制御
グループ制御オブジェクトは、**その下のレイヤー(`対象レイヤー数`分、0なら以降すべて)にある、時間が重なるオブジェクト**に共通変換を与える親のような存在。

パラメータ: `X, Y, Z`、`拡大率`、`透明度`、`X/Y/Z軸回転`、`対象レイヤー数`、`上のオブジェクトでクリッピング`、`カメラ制御の対象` **(要検証: 名称と一覧)**。

計算(グループの基点=グループの`X,Y,Z`とする):

```
child_world = G_T(X,Y,Z) · G_R · G_S · child_local
```

- 子の座標は**グループ制御の(X,Y,Z)を原点とした位置**になる。グループを回転/拡大すると、子は各自の中心で自転するだけでなく、**グループ原点を中心に公転・拡縮する**。
- 透明度は乗算(子×グループ)。
- 入れ子(グループ制御の下にグループ制御)は、内側から外側の順に適用する。
- 子の`基点(cx,cy)`は子自身の自転中心のままで、グループの基点とは独立。
- movutlの既存の`Entity::group_guid_`・`EntityType_Group`は「グループ化」の枠であり、上記のような**変換を親から継承する処理は未実装**。

## 3. After Effects の仕様
- アンカーポイントは**レイヤー自身の座標**(原点=レイヤー左上、px、Y下向き)。既定はレイヤー中心。
- 位置は**アンカーがコンポ(または親)のどこに来るか**。
- 変換: `p' = T(position) · R · S · T(-anchor) · p`。回転順は Orientation → X → Y → Z。
- 親子付け: 子の位置は**親のアンカーポイントを原点**とした座標になる。
- アンカーだけ数値変更すると見た目が動く(Pan Behindツールは位置を自動補正して見た目を保つ)。
- ポイントテキスト: アンカーはベースライン上の揃え位置(左揃え=行頭、中央揃え=行の中央、右揃え=行末)にあり、揃えを変えるとテキストがアンカーに対して動く。ボックステキストの既定アンカー位置は **(要検証)**。

## 4. Premiere Pro の仕様
- モーション効果の`アンカーポイント`は**素材の座標**(原点=素材左上、px)、`位置`は**シーケンス座標**。既定は各々の中心。
- 変換式はAEの2Dと同じ。回転・拡大はアンカー中心。Zや3Dは無い。
- アンカーだけ変えると見た目が動く(位置で補正しない限り)。
- テキスト(エッセンシャルグラフィックス): 段落の揃えとアンカーの関係は **(要検証)**。

| 項目 | AviUtl | AE | Premiere | movutl現状 |

## 6. movutl の統一仕様案

### 6.1 座標の約束
1. **`pos` は AviUtl 方式**(コンポ中心原点、Y下向き)で「基点の位置」を表す。AE/Premiereとの変換は `pos_ae = pos + comp_size/2`(基点が中心のときの単純なオフセット)。
2. **`anchor` は AviUtl 方式**(画像中心からのオフセット、既定0)。AE/Premiereとは `anchor_ae = anchor + img_size/2`。
3. **揃え(テキスト)は既定の`anchor`に加算**(`a = (ax*w/2, ay*h/2)`)する(2.4)。ユーザーが指定する`anchor`と別に持ち、保存する値は`align`のみ。
4. スケールは**X/Yの2値**で持つ。単位は%に統一(0-1のImage/Textは変換)。回転は**度に統一**、Z回転は時計回りが正 **(要検証)**。透明度は0-1(exoからは変換)。

### 6.2 描画手順(2D)
`Image::copyto` は「画像中心まわりで回転・拡大」する現行のままにして、**基点分のずれを`center`の側で補正**すればよい。

```
img_center_screen = comp_center + pos - R·S·anchor_eff      // 画像中心の描画位置
pmin              = img_center_screen - (w,h)/2 * S          // copyto へ渡す左上
copyto(dst, pmin, S, angle, alpha, blend)
```

- 現行`copyto`は「pmin+(w/2,h/2)」を画像中心に使うため(`image.cpp:136`)、pminを上記で計算して渡せば、`copyto`本体は変更不要。
- 非等方スケール(縦横比)を入れる場合のみ`copyto`の拡張が必要。

### 6.3 グループ制御
`GroupEntt`(仮)が `pos/scale/rotation/alpha` と `対象レイヤー数` を持ち、レンダリング時に対象Entityの変換行列へ左から掛ける。

```
M_child_world = M_group · M_child_local          // M = T(pos)·R·S、pos=グループ原点
alpha_world   = alpha_group * alpha_child
```

対象判定: 「グループ制御より下のレイヤー」かつ「フレーム範囲が重なる」かつ`対象レイヤー数`以内。

### 6.4 exoインポート
- Movie以外は取り込み時に原点が食い違うので、**Entityの原点を6.1で統一してからexo変換(`X,Y`をそのまま`pos`へ)**にするのが望ましい。統一までの暫定として `pos = (cw - w)/2 + X` をImage/Shape/Textに適用する手もあるが、二度手間になる。
- テキストの`align`→`ax,ay`変換表は2.4のとおり。
